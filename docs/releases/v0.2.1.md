## Purpose

Version `0.2.1` is the distribution release following `v0.2.0`. It does not
introduce a broader engineering claim. It packages the already reviewed MCPB and
Registry preparation and adds guarded PyPI Trusted Publishing.

The release is intended to make the Python server installable with:

```bash
python -m pip install diptrace-mcp==0.2.1
```

The Python package installs the MCP server and command-line entry points. It
does not install the Windows DipTrace bridge plug-in automatically.

## Included changes

- package and fallback version aligned to `0.2.1`;
- deterministic Windows MCPB builder and SHA-256 output;
- MCPB manifest and user-facing bundle instructions;
- official MCP Registry `server.json` template and generator;
- canonical ownership marker `io.github.fireostendere/diptrace-mcp`;
- PyPI wheel and source-distribution validation;
- manual, tag-bound PyPI Trusted Publishing through GitHub OIDC;
- clean wheel and sdist installation smoke;
- release, installation, and distribution documentation for PyPI, MCPB,
  Registry, and Smithery.

## PyPI publication boundary

The authorized publisher identity is planned as:

- owner: `fireostendere`;
- repository: `mcp_diptrace`;
- workflow: `.github/workflows/pypi.yml`;
- environment: `pypi`;
- project: `diptrace-mcp`.

The publish job is intentionally separate from the build job. It receives only
the previously validated wheel and sdist, has `contents: read` and
`id-token: write`, and uses the pinned PyPA publishing action. No long-lived
PyPI token is stored.

Publication is allowed only by manually dispatching the workflow from the exact
annotated `v0.2.1` tag with `publish=true`. Branch, `main`, lightweight-tag, and
mismatched-tag publication requests fail closed.

## Known limitations

- Windows executables are unsigned.
- Production readiness is not claimed.
- Universal DipTrace 5.x compatibility is not claimed.
- Real acceptance remains incomplete for several Windows, DipTrace, Codex,
  Claude Desktop, elevated-install, and custom-state paths.
- Q1 Component Angle GUI/re-export evidence remains `NOT_RUN`.
- The MCPB contains the self-contained Windows stdio server but does not silently
  install the DipTrace bridge plug-in.
- The Python package does not install or configure the Windows bridge.
- Novarm/DipTrace endorsement, affiliation, approval, or redistribution
  permission is not claimed.
